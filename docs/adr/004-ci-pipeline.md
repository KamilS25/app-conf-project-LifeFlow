# ADR 004. Базовый CI для LifeFlow

## Статус

Принято при слиянии [PR №13](https://github.com/KamilS25/app-conf-project-LifeFlow/pull/13) после обязательного approval другого участника.

Автор решения — Салахетдинов Камиль (`KamilS25`).

## Контекст

LifeFlow использует GitHub Flow с защищённой веткой `main`, uv и Gitleaks в pre-commit. Проверки на машине автора и ревью полезны до публикации, но результат локального запуска не входит в правила слияния. Для практической №5 нужны воспроизводимые проверки стиля, формата, типов и секретов на каждом PR.

## Рассмотренные варианты

| Вариант | Преимущества | Ограничения |
| --- | --- | --- |
| Pre-commit и ручная проверка | Быстрая обратная связь до коммита | GitHub не получает обязательного статуса, а результаты зависят от локального окружения |
| Один джоб со всеми проверками | Одно условие слияния | Сбой на раннем шаге скрывает результаты последующих проверок, в том числе сканирования секретов |
| Независимые `lint` и `secrets` | Обе проверки запускаются параллельно и имеют отдельные статусы | Два джоба выполняют checkout независимо |

## Решение

1. В [workflow `ci.yml`](../../.github/workflows/ci.yml) запустить независимые `lint` и `secrets` на каждом PR в `main` и при push в `main`. Для workflow достаточно разрешения `contents: read`.
2. В `lint` использовать Python из `.python-version`, uv и установку из `uv.lock`. Выполнять `ruff check`, `ruff format --check` и `mypy` с плагином `pydantic.mypy`. Инструменты закреплены в группе `dev`.
3. В `secrets` проверять отслеживаемые игнорируемые файлы, затем запускать Gitleaks 8.30.1 для файлов и всей доступной истории Git (`fetch-depth: 0`, `--log-opts=--all`). Из [ADR 003](003-configuration.md) сохраняется тот же образ Gitleaks и сканирование индекса перед коммитом. Проверки в CI маскируют значения находок.
4. Базовый [`protect-main`](https://github.com/KamilS25/app-conf-project-LifeFlow/rules/24886325) требует `lint` и `secrets` от GitHub Actions и один approval другого участника. Строгое обновление ветки перед merge выключено. Красный обязательный статус блокирует слияние.
5. [ADR 005](005-testing-and-build.md) добавляет `test`, `build` и `publish`, описывает права публикации и расширяет перечень обязательных проверок.

## Обоснование

Параллельный запуск даёт результат Gitleaks даже при сбое линтера. Сканирование текущих файлов выявляет секреты в содержимом PR, а проверка истории — значения, которые добавили и затем удалили в одном наборе изменений. Закреплённые зависимости позволяют повторить проверки локально, а GitHub проверяет их результат перед слиянием.

## Последствия и проверка

- На первом прогоне Ruff запросил форматирование `settings.py`, а GitHub подтвердил `BLOCKED` при обязательном красном `lint`. [Диагностика и блокировка](https://github.com/KamilS25/app-conf-project-LifeFlow/pull/13#issuecomment-7137978890)
- После форматирования mypy потребовал уточнить аргумент `make_conninfo` и учесть, что `Settings()` читает окружение. Исправления прошли следующий прогон. [Диагностика mypy](https://github.com/KamilS25/app-conf-project-LifeFlow/pull/13#issuecomment-7138009357)
- Сканирование истории требует загрузки всех доступных коммитов. При росте истории время `secrets` может увеличиться. Локальному pre-commit по-прежнему нужен Docker.

Замер на зелёном PR-прогоне от 24.11.2026, коммит `749acc0`. API GitHub показывает время с точностью до секунд. [Прогон GitHub Actions](https://github.com/KamilS25/app-conf-project-LifeFlow/actions/runs/45439739778)

| Джоб или шаг | Время |
| --- | --- |
| `lint` | 10 с (измерено) |
| `ruff check` | менее 1 с (измерено) |
| `ruff format --check` | менее 1 с (измерено) |
| `mypy` | 2 с (измерено) |
| `secrets` | 8 с (измерено) |
| Gitleaks по файлам | 3 с (измерено) |
| Gitleaks по истории | 1 с (измерено) |
