## Контекст

Проект LifeFlow разрабатывается на Python с использованием FastAPI и PostgreSQL. В команде необходимо обеспечить единый и воспроизводимый способ управления зависимостями для локальной разработки и запуска приложения в Docker.

Менеджер зависимостей должен обеспечивать:
- централизованное описание зависимостей проекта;
- фиксацию версий прямых и транзитивных зависимостей;
- воспроизводимую установку пакетов на компьютерах разработчиков;
- совместимость с Docker-сборкой;
- удобное добавление и обновление библиотек.

На момент принятия решения проект использует `pyproject.toml` и `uv.lock`.

## Рассмотренные варианты

Рассмотрены три варианта управления зависимостями:

| Критерий | pip + requirements.txt | Poetry | uv |
|---|---|---|---|
| Описание зависимостей | `requirements.txt` | `pyproject.toml` | `pyproject.toml` |
| Фиксация версий | Через отдельный файл с версиями | `poetry.lock` | `uv.lock` |
| Воспроизводимая установка | Требует дополнительной организации фиксации | Поддерживается | Поддерживается |
| Управление зависимостями | Базовые команды установки | Полноценный менеджер проекта | Полноценный менеджер проекта |
| Интеграция с Docker | Требует настройки | Поддерживается | Поддерживается |
| Дополнительные инструменты | Могут потребоваться | Poetry | Не требуются для выбранного сценария |

### Вариант 1. pip + requirements.txt

Стандартный инструмент установки Python-пакетов. Прост в использовании, но для полноценного управления проектными зависимостями и фиксации транзитивных версий требует дополнительной организации процесса.

**Недостатки:** отсутствие встроенного механизма блокировки зависимостей проекта и необходимость самостоятельно поддерживать согласованность конфигурации.

### Вариант 2. Poetry

Менеджер зависимостей, использующий `pyproject.toml` и собственный lock-файл. Поддерживает управление зависимостями и воспроизводимую установку.

**Недостатки:** для перехода на него потребовалось бы внедрить дополнительный инструмент и адаптировать уже существующую конфигурацию проекта.

### Вариант 3. uv

Современный менеджер Python-зависимостей, работающий с `pyproject.toml` и `uv.lock`. Поддерживает добавление пакетов, синхронизацию окружения и установку зависимостей по lock-файлу.

**Преимущества:** уже используется в проекте LifeFlow, позволяет сохранить существующую конфигурацию и интегрирован в Docker-сборку.

## Решение

Для проекта LifeFlow выбран менеджер зависимостей **uv**.

Основные правила работы:

1. Основной файл описания зависимостей — `pyproject.toml`.
2. Файл `uv.lock` хранится в Git и фиксирует версии зависимостей.
3. Для синхронизации локального окружения используется команда:

   ```powershell
   uv sync --locked
   ```

4. Для добавления новой зависимости используется команда:

   ```powershell
   uv add <package>
   ```

5. Для добавления зависимости разработки используется:

   ```powershell
   uv add --dev <package>
   ```

6. При изменении зависимостей необходимо сохранять обновлённые `pyproject.toml` и `uv.lock`.

7. В Dockerfile зависимости устанавливаются до копирования исходного кода:

   ```dockerfile
   COPY pyproject.toml uv.lock ./
   RUN uv sync --locked --no-dev --no-install-project
   ```

8. После копирования исходного кода приложение запускается командой:

   ```dockerfile
   CMD ["uv", "run", "--no-sync", "uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
   ```

9. Секреты и локальные настройки окружения не включаются в файлы зависимостей и не публикуются в Git.

10. Версия Python для локального запуска задана в `.python-version` и совпадает с версией базового образа.

## Обоснование

Выбор uv обусловлен тем, что проект уже использует `pyproject.toml` и `uv.lock`. Это позволяет избежать миграции на другой инструмент, сохранить текущую структуру зависимостей и использовать один механизм установки пакетов как при локальной разработке, так и при сборке Docker-образа.

## Последствия

Положительные последствия:
- зависимости проекта централизованно описаны в `pyproject.toml`;
- версии пакетов фиксируются в `uv.lock`;
- локальная и контейнерная установка используют единый менеджер;
- зависимости устанавливаются отдельным слоем Docker-образа, что позволяет использовать кеширование при повторной сборке;
- производственные зависимости отделяются от инструментов разработки.

Ограничения:
- для работы с зависимостями разработчикам необходимо установить uv;
- при изменении состава зависимостей необходимо обновлять и коммитить lock-файл.

На Windows с Docker Desktop холодная сборка с загрузкой базовых образов и запуск стека на новом томе заняли 44,9 секунды. Пересборка после изменения строки в `main.py` заняла 2,4 секунды. Docker повторно выполнил `COPY . .` и взял слой `RUN uv sync --locked --no-dev --no-install-project` из кэша.

## Риски и митигация

- Если `pyproject.toml` и `uv.lock` разойдутся, `uv sync --locked` завершится ошибкой при локальной установке и сборке образа. В PR с новыми зависимостями проверяем оба файла.
- Если обновление uv меняет формат lock-файла, одновременно проверяем сборку с закреплённой версией uv в `Dockerfile`.
